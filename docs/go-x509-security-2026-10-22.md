# Go certificate-validation security update — 2026-10-22

PR #32's [PageRank job](https://github.com/fullerkris/mifolyo/actions/runs/39836673334/job/120026710953)
at `18fdc5045c6a05dfa661a3ead90f886b402697d1` passed service initialization,
MongoDB 9.0.4 verification, `go vet`, and its race-enabled test suite. The
subsequent `govulncheck` step exited 3 on
[GO-2026-6809 / CVE-2026-111943](https://pkg.go.dev/vuln/GO-2026-6809), published
on 2026-10-21. The finding is in Go 1.26.9's `crypto/x509.Certificate.Verify`;
Go 1.26.10 adds rejection of compromised intermediate certificates.

## Patch

- Pin PageRank and Spider's module toolchains, Docker builders and all three
  Go setup steps in CI to **Go 1.26.10**.
- Advance the existing exact-version differential-oracle assertions and
  Unicode generator to that same patch release.
- Verify the updated generator/provenance against the sealed oracle and Lua
  data. The generated data's historical identity remains bound to its bytes.

This follows the [October 9 toolchain update](go-http2-security-2026-10-09.md).
The existing module versions and Spider's exact normalization replacement are
still the generator's required inputs. The vulnerability scan remains enabled.

## Local verification

- `govulncheck` v1.7.0, targeting Linux/amd64 with Go 1.26.10: both services
  pass with zero reachable or imported-package vulnerabilities. PageRank has
  one module-only notice in code it does not call.
- PageRank: **14 top-level tests pass under the race detector, zero skips**,
  including publication against a fresh MongoDB 9.0.4 fixture.
- Both services: `go vet`, `go mod verify`, and Linux/amd64 builds pass.
- Offline Unicode regeneration checks all **1,114,112 code points** and
  reproduces the sealed oracle and Lua data exactly.
- All six URL/Unicode Go/Lua/Python race-test roots pass: five in the initial
  run, including real Lua lookups for every code point, and the Python oracle
  after selecting Python 3.12 instead of the workstation's default Python 3.9.
  That oracle compares 10,954 URLs, 37,225 normalization cases and 18 codec
  chunks. The initial Python 3.9 failure was `dataclass(slots=True)` support.
- Workflow linting and whitespace checks pass. Fresh exact-head hosted CI is
  required after publication.

The initial local PageRank fixture allocated only 512 MiB of temporary database
storage. After MongoDB initialization, its 326,959,104 available bytes were
below the 524,288,000-byte minimum for building an index on a populated
collection. A direct `mongosh` probe reproduced the refusal. A fresh 2 GiB
temporary fixture passed the index probe and the complete PageRank suite;
each owned fixture was removed after use. This local fixture-sizing issue is
separate from the hosted job's vulnerability-scan failure.
